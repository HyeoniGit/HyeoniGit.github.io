나이츠 프론티어 미션으로 퍼징이 무엇인지, 그리고 여러 종류의 퍼저가 어떻게 다른지 공부하며 정리한 내용이다.

## 퍼징이란

프로그램에 비정상적이거나 예상 못 한 입력을 자동으로 대량 투입해서, 크래시·메모리 오류·행(멈춤) 같은 이상 동작을 유발하는 입력을 찾아내는 취약점 테스트 기법이다.

**많이 잡는 버그** : 버퍼 오버플로, use-after-free, 널 포인터 역참조, 정수 오버플로, assert 실패 등.

## 기본 동작 흐름

```
입력 생성 → 타겟 실행 → 동작 감시 → 결과 피드백 → 다음 입력 생성 → ...
```

## 핵심 용어

1. **Seed / Corpus** : 시작 입력 샘플(seed)의 모음(corpus)
2. **Mutation** : 기존 입력을 비트 뒤집기, 바이트 삽입, 값 교체 등으로 변형
3. **Coverage** : 실행이 코드의 어디까지 도달했는지. 새 경로를 연 입력을 가치가 있다고 보고 corpus에 추가한다 (점점 깊이 들어가게)
4. **Crash triage** : 터진 입력을 분류, 최소화 (어느 부분이 원인인지 파악)

## 퍼저 분류 기준

### 1. 입력 생성 방식
- **변이 기반** : 기존 샘플을 변형해서 생성 (파일 파서, seed를 구하기 쉬운 것에 적합)
- **생성 기반** : 입력 형식을 정의해 처음부터 만듦 (구조가 엄격한 것에 적합)

### 2. 타겟 내부 정보를 얼마나 아느냐

| 유형 | 커버리지 정보 | 특징 |
|---|---|---|
| Black-box | 없음 | 그냥 넣어보고 터지는지 확인. 빠르지만 얕게 확인 |
| Grey-box | 일부 | coverage를 이용해 방향을 잡는다. 속도와 깊이의 균형이 좋아 요즘 주로 사용 |
| White-box | 많음 | 코드를 정밀 분석해 수학적으로 계산. 무겁고 느리지만, 까다로운 조건도 정확히 통과할 수 있음 |

### 3. 계측 방식 (커버리지를 어떻게 수집하냐)
- **컴파일 타임 계측** : 소스를 특수 컴파일러로 빌드. 빠르지만 소스 필요
- **동적 바이너리 계측(DBI)** : 소스 없이 바이너리에 삽입. 느리지만 소스 불필요
- **하드웨어** : CPU 기능으로 추적. 추가 비용(오버헤드) 적음

## 대표적인 퍼저들

| 퍼저 | 유형 | 소스 | 대상 | 특징 |
|---|---|---|---|---|
| **AFL / AFL++** | 변이, grey-box | 필요 (없으면 QEMU 모드) | 파일 입력 프로그램, Linux 중심 | 가장 유명 |
| **libFuzzer** | 변이, grey-box | 필요 | 함수·라이브러리 단위 | LLVM 내장, 타겟을 라이브러리로 링크. 매우 빠름 |
| **honggfuzz** | grey-box | 선택 | 파일, 네트워크 | SW 계측 + 하드웨어 지원 |
| **Jackalope** | black-box | 불필요 | 폐쇄 소스 바이너리 | 소스 없이 DBI로 계측. 크로스 플랫폼(Win·macOS·Linux·Android) |
| **syzkaller** | 생성 + 변이, grey-box | 커널 코드 | OS 커널 | 시스템 콜 시퀀스를 생성·변이. KCOV로 커버리지 |
| **boofuzz** | 생성, black-box | 불필요 | 네트워크 프로토콜 | 아무 바이트나 변형하면 서버가 바로 연결을 끊으므로, 형식을 지켜 블록으로 정의 |

## 퍼징의 장점과 한계

**장점**
- 사람이 발견하지 못한 edge case를 대량으로 찾을 수 있다.
- 실제 CVE를 많이 발굴할 수 있다.

**한계**
- 커버리지가 특정 지점에서 막히면 그 너머를 갈 수 없다. (복잡한 체크섬·암호 검증은 통과할 수 없음 → redqueen, laf-intel으로 완화 가능)
- 깊은 로직·논리 취약점은 잘 못 잡는다. (크래시가 나지 않는 버그)
- seed 품질에 성능이 크게 좌우된다.

## 용어 정리

- **LLVM** : 컴파일러 제작용 오픈소스 프레임워크/도구모음. C/C++ 같은 코드를 기계어로 바꾸는 엔진. libFuzzer, SanitizerCoverage, ASan 같은 기능이 내장되어 있어서 많이 쓴다.
- **KCOV** : 리눅스 커널에 내장된 커버리지 수집 기능.
- **CVE** : 공개적으로 등록된 취약점 고유 번호표.
- **redqueen** : 실행 중 프로그램이 입력을 무슨 값과 비교하는지 엿봐서, 그 값을 입력에 그대로 넣어 까다로운 조건을 통과시킴.
- **laf-intel** : 한 번에 통째로 하는 큰 비교를 1바이트씩 쪼갠 여러 비교로 변환해서, 퍼저가 한 바이트씩 단계적으로 뚫게 해줌.
- **checksum(체크섬)** : 데이터가 손상·변조됐는지 확인하는 검증값. 퍼저가 입력을 변형하면 체크섬이 안 맞아 입구에서 튕겨 안쪽을 못 본다.
