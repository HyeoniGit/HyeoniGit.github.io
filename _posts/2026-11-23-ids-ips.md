나이츠 프론티어 미션으로 침입 탐지·방지 시스템(IDS/IPS)을 공부하며 정리한 내용이다. 동작 원리, 유형, 활용 방법, 장단점, 그리고 둘의 차이까지 정리한다.

## IDS / IPS란

- **IDS** (Intrusion Detection System, 침입 탐지 시스템) : 트래픽, 로그를 감시하다가 공격으로 의심되면 탐지하고 알림을 준다.
- **IPS** (Intrusion Prevention System, 침입 방지 시스템) : 탐지 + 실시간으로 차단, 차단 조치까지 한다.

## IDS vs IPS

| 구분 | IDS | IPS |
|---|---|---|
| 역할 | 탐지 + 알림 | 탐지 + 차단 |
| 위치 | 트래픽 경로 밖 (경로 밖에서 구경) | 트래픽 경로 위 (트래픽에 실제로 끼어 있음) |
| 대응 | 수동 | 능동 (자동 차단) |
| 트래픽 영향 | 없음 | 있음 |
| 오탐 시 | 필요없는 알림만 발생 | 정상 트래픽까지 차단 |

## 장단점

**IDS**
- 장점 : 트래픽에 영향이 없고, 부담 적게 넓게 감시한다. 오탐이 발생해도 통신이 끊기지 않는다.
- 단점 : 실제로 차단할 수는 없고, 탐지해도 사람이 대응해야 한다.

**IPS**
- 장점 : 공격을 실시간으로 자동 차단한다.
- 단점 : 오탐 시 정상 서비스를 차단할 위험이 있다. inline이라 지연, 성능, 운영 튜닝 부담이 크다.

## 동작 원리

**1. 시그니처 기반**
알려진 공격 패턴과 비교해서 일치하면 탐지한다.
- 장점 : 알려진 공격에 정확하게 대응하고, 오탐이 적다.
- 단점 : 새로운 공격은 잡지 못한다. 규칙 DB를 계속 업데이트해줘야 한다.

**2. 이상 기반**
평소 정상 상태를 학습해두고, 거기서 벗어나면 의심한다.
- 장점 : 알려지지 않은 공격도 탐지 가능하다.
- 단점 : 오탐이 많다. 기준을 세우기 어렵다.

**3. 상태 기반 프로토콜 분석**
프로토콜이 정상적으로 지켜야 할 규칙을 알고, 그에 어긋나는 비정상 사용을 탐지한다.

## 유형 (어디서 감시하느냐)

**1. NIDS / NIPS (Network 기반)**
네트워크 구간을 지나는 트래픽을 감시한다.
- 장점 : 센서 하나로 여러 호스트를 한 번에 커버한다.
- 단점 : 암호화된(HTTPS 등) 트래픽은 내용을 못 본다.

**2. HIDS / HIPS (Host 기반)**
특정 서버/PC에 설치돼서 그 호스트의 로그, 파일, 프로세스를 감시한다.
- 장점 : 암호화된 트래픽도 호스트에선 복호화된 상태라 볼 수 있다.
- 단점 : 호스트마다 설치해야 해서 관리 범위가 좁다.

→ 그래서 NIDS(넓게) + HIDS(좁게) 로 함께 쓴다.

## 활용 방법

**1. IDS 배치**
미러 포트나 TAP으로 복사본을 받아서 감시한다. 원본 통신에는 영향이 없다.

**2. IPS 배치**
경로 중간에 inline으로 끼워 넣는다. 트래픽이 반드시 지나가는 길 한가운데에 직접 놓는다.

**3. 네트워크 순서**
`인터넷 → 방화벽 → IDS/IPS → 내부망` 순서로, 방화벽을 통과한 트래픽만 IDS/IPS가 내용까지 깊게 검사한다.

**4. 통합 추세**
최근에는 방화벽과 IPS + 기타 기능을 한곳에 통합시킨다. 이를 차세대 방화벽(NGFW)이라 한다.

**5. 로그 관리**
탐지 결과는 모든 장비의 로그, 알림을 한곳에 모으는 시스템인 SIEM으로 모아서 상관분석하고 로그를 관리한다.

## 다른 보안 장비와의 차이

1. **vs 방화벽** : 방화벽은 IP, 포트 기반으로 허용하고 차단한다. 내용은 깊게 보지 않는다.
2. **vs WAF** : WAF는 웹(HTTP) 공격에 특화된 방어를 한다.
